## Общая карта

Номера O и D указывают на строки независимых карт, чтобы сохранить различия оценок.
«Условие интеграции» — обязанность приложения; «предложение» — выбор API или документации.
Они не считаются автоматически дефектами пакета.

Замечание по headers: наличие `replace=false` подтверждено в исходниках.
Поведение Content-Type зависит от PHP SAPI; ревью не доказывает его дублирование на реальном сервере.
Проверять следует фактический HTTP-ответ, включая Cache-Control и повторные допустимые headers.

## Что исправлять первым

1. Стабилизировать адрес назначения: запретить dot segments в placeholders, определить origin-only контракт,
   решить вопрос абсолютных URL и убрать ненужный автоматический redirect opt-in.
2. Сохранить форму JSON и большие идентификаторы при пересылке; отдельно определить представление для адаптера.
3. Проверить замену уже установленных headers на настоящей HTTP-границе и зафиксировать политику.
4. Согласовать публичное имя и термин адаптера перед стабильным выпуском.
5. После этого подготовить обычную Composer-установку и проверить первый реальный write-сценарий в приложении.

Первые три пункта относятся к поведению библиотеки. Проверки verb/CSRF/ownership/lifecycle относятся к интеграции.
Косметические предложения не требуют отдельной абстракции или обязательного переименования API.

## Название

Предпочтительный вариант для текущего объёма поддержки:

| Компонент | Рекомендация |
| --- | --- |
| Название продукта | **Yii 1 Strangler Proxy** |
| Composer | **`cosmira/yii1-strangler-proxy`** |
| Репозиторий | **`yii1-strangler-proxy`** |
| Краткое описание | Поэтапная миграция JSON API из Yii 1.1 с сохранением проверок доступа и адаптацией контрактов. |

`Yii 1` сразу снимает ожидание поддержки Yii2. `Strangler` обозначает способ миграции,
а `Proxy` — пересылку запросов. Подзаголовок уточняет JSON API и роль фильтра.
PHP namespace `Cosmira\Strangler`, настройки и headers не нужно менять ради названия пакета.

Один агент предпочитает `yii1-strangler-proxy`, второй — `yii-strangler-proxy` с явным Yii 1.1 в заголовке.
Оба считают пользовательский вариант **Yii Strangler Proxy** содержательнее текущего Composer name.
Для нынешнего Yii1-only пакета точность важнее небольшого сокращения имени.

| Альтернатива | Оценка |
| --- | --- |
| `strangler` | Коротко, но скрывает платформу и назначение. |
| `yii-strangler-proxy` | Хороший второй выбор; поколение Yii остаётся неясным из имени. |
| `yii-strangler` | Короче, но не объясняет механизм перехода. |
| `yii-api-bridge` | Слишком широкое обещание универсальной интеграции API. |
| `yii-migration-proxy` | Migration может ассоциироваться с миграциями БД. |

Доступность имён и публикация текущего пакета не подтверждены. Это рекомендация, не резервирование имени.
Переименование package/repository в рамках этого ревью не выполнялось.

Перед реализацией проверить внешних потребителей и Packagist, затем согласованно обновить Composer name,
repository URLs, install snippets, badges и внешние ссылки.
Packagist предупреждает, что имя опубликованного пакета нельзя изменить: для него потребуется отдельный переход.
[Правила Packagist](https://packagist.org/about).

GitHub обычно сохраняет перенаправления старых repository URLs, но рекомендует обновить remotes;
повторное использование старого имени прекращает эти перенаправления.
[Правила переименования GitHub](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository).

## Итог ревью

Основная модель уже понятна и удобна: один фильтр, явные маршруты, флаг, небольшой адаптер, отсутствие replay.
Следующий шаг — несколько конкретных исправлений границ JSON и HTTP, затем имя и установка.
Переписывать пакет в универсальный gateway или framework для миграций оснований нет.
